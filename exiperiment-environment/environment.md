# 实验环境与系统架构

## 1. 研究背景与目标

本项目第二部分以自主编写的高性能矩阵乘法程序 `Matrix_mul.c` 为研究对象，结合实际服务器的硬件架构与软件环境，分析程序采用的底层性能优化技术。

研究重点包括：

- CPU 多级缓存与数据局部性
- 多级矩阵分块（Multi-level Blocking）
- 矩阵数据打包（Packing）
- AVX SIMD 指令优化
- 寄存器分块与微内核设计
- OpenMP 多线程并行
- NUMA 内存访问与线程亲和性

本部分不仅分析代码实现，还将研究优化策略与实际硬件架构之间的关系。

## 2. 硬件环境

### 2.1 处理器基本信息

本项目使用双路 Intel Xeon 服务器进行开发和实验。

| 硬件参数 | 实际配置 |
|---|---|
| CPU 型号 | Intel Xeon E5-2620 |
| 标称主频 | 2.00 GHz |
| Socket 数量 | 2 |
| 每个 Socket 物理核心数 | 6 |
| 物理核心总数 | 12 |
| 每个核心逻辑线程数 | 2 |
| 逻辑 CPU 总数 | 24 |
| Hyper-Threading | 已开启 |
| 指令集支持 | AVX |

### 2.2 CPU 拓扑结构

根据 `lscpu -e` 实测结果：

| 处理器 | NUMA 节点 | CPU 编号 | 物理核心数 |
|---|---|---|---:|
| Socket 0 | Node 0 | 0–5、12–17 | 6 |
| Socket 1 | Node 1 | 6–11、18–23 | 6 |

两个 Socket 分别对应一个 NUMA 节点。

每个物理核心对应两个逻辑 CPU。

### 2.3 CPU Cache 层次结构

根据 Linux 系统目录 `/sys/devices/system/cpu/cpu0/cache/` 获取 CPU 0 的缓存信息。

| 缓存层级 | 类型 | 容量 | 共享范围 |
|---|---|---:|---|
| L1 Data | 数据缓存 | 32 KB | 单个物理核心 |
| L1 Instruction | 指令缓存 | 32 KB | 单个物理核心 |
| L2 | 统一缓存 | 256 KB | 单个物理核心 |
| L3 | 统一缓存 | 15 MB | Socket 0 的 6 个核心 |

CPU 0 的 L3 Cache 共享范围为 `0-5,12-17`。

两个 Socket 拥有各自的 L3 Cache，不能将它们视为一个统一共享缓存。

注：Socket 1 的缓存信息尚待单独确认。

### 2.4 NUMA 内存架构

服务器包含两个 NUMA 节点。

| 参数 | NUMA Node 0 | NUMA Node 1 |
|---|---:|---:|
| CPU 编号 | 0–5、12–17 | 6–11、18–23 |
| 总内存 | 16355 MB | 16384 MB |
| 当前空闲内存 | 14156 MB | 14132 MB |

NUMA 距离矩阵：

| 访问方向 | 距离 |
|---|---:|
| Node 0 → Node 0 | 10 |
| Node 0 → Node 1 | 21 |
| Node 1 → Node 0 | 21 |
| Node 1 → Node 1 | 10 |

本地 NUMA 访问距离为 10，跨节点访问距离为 21。

这意味着程序在多线程执行时，需要考虑线程所在节点与数据所在节点之间的关系。

### 2.5 硬件环境小结

当前服务器具有以下特点：

1. 双路处理器架构，包含两个 NUMA 节点。
2. 共 12 个物理核心、24 个逻辑线程。
3. 每个物理核心具有独立的 L1、L2 缓存。
4. 每个 Socket 具有共享的 L3 缓存。
5. 支持 AVX 256-bit SIMD 指令。
6. 两个 NUMA 节点之间存在远程内存访问开销。

| 头文件或接口 | 主要作用 |
|---|---|

### 3.4 并行与指令集支持

**OpenMP**

通过 OpenMP 创建并行区域，组织多线程矩阵分块计算。

**AVX**

使用 256-bit AVX 向量寄存器，每个寄存器能够容纳 8 个单精度浮点数。

**内存对齐**

通过 `posix_memalign` 实现 64 字节内存对齐，为向量化数据访问提供对齐条件。

具体编译参数和实际运行时配置仍需结合原始编译命令确认。

## 4. 研究对象与优化实现

本项目第二部分的核心研究对象为：

`Matrix_mul.c`

根据现有实现记录，程序采用以下优化技术：

| 优化技术 | 实现参数 |
|---|---|
| 多级分块 | MC = 64、NC = 128、KC = 256 |
| 微内核尺寸 | MR = 4、NR = 16 |
| 数据打包 | B 矩阵 Packing |
| SIMD | AVX 256-bit |
| 寄存器分块 | 4×16 微内核 |
| 内存对齐 | 64 Bytes |
| 并行调度 | OpenMP Dynamic Scheduling |

后续将结合源码逐项分析这些技术的实现方式及其与服务器硬件架构之间的关系。

## 5. 后续研究方向

1. 多级矩阵分块参数与 CPU Cache 容量之间的关系。
2. B 矩阵 Packing 对内存访问局部性的改善。
3. AVX 微内核的向量计算与寄存器复用机制。
4. OpenMP 多线程调度对整体性能的影响。
5. 双路 NUMA 架构下的内存访问与线程亲和性。
6. 不同优化技术之间的协同作用。
