# 02. Cache Blocking: Matrix Multiplication Optimization

## 1. 实验目的

研究矩阵分块技术对矩阵乘法性能的影响，通过将大矩阵划分为多个小块，改善数据访问局部性，提高 CPU Cache 利用率。

本实验重点研究不同分块大小对执行时间的影响，并分析理论缓存容量与实际最优分块大小之间的关系。

## 2. 实验原理

传统矩阵乘法在计算过程中需要反复访问矩阵 A、B 和 C。

当矩阵规模较大时，数据访问可能频繁涉及较低层次的存储结构，从而增加访存开销。

Cache Blocking 将矩阵划分为多个 m × m 的小块，每次计算一组对应的数据块，减少数据重复访问，提高缓存局部性。

分块大小 m 是本实验的核心调节参数。

## 3. 实验环境与参数

- 矩阵规模：N = 8192
- 数据类型：float
- 单个元素大小：4 Bytes
- L1 Cache：32 KB
- L2 Cache：256 KB
- L3 Cache：15 MB
- 优化方法：矩阵分块
- 并行方法：OpenMP
- 调度策略：schedule(static)
- 循环展开：collapse(2)

## 4. 分块大小的理论选择

根据原实验报告，初始分块大小选择为 m0 = 128。

单个 128 × 128 矩阵块的大小：

128 × 128 × 4 = 64 KB

计算时需要访问 A、B 对应数据块，其总大小约为 128 KB；若考虑 C 的结果块，三个矩阵块的总工作集约为 192 KB。

该容量低于报告所记录的 256 KB L2 Cache 容量，因此将 128 作为合理的初始分块大小。

## 5. 历史实验结果

实验在 N = 8192 的条件下调整分块大小。

| 分块大小 m | 执行时间(s) | 加速比 |
|---:|---:|---:|
| 不分块 | 331.927399 | 1.00 |
| 32 | 39.966442 | 8.31 |
| 64 | 31.168053 | 10.65 |
| 128 | 27.783229 | 11.95 |
| 256 | 25.928071 | 12.80 |
| 512 | 81.679690 | 4.06 |

数据来源：原始实验报告，表 2-3。

## 6. 实验结果分析

实验结果显示，随着分块大小从 32 增加到 256，执行时间逐渐下降。

当分块大小达到 256 时，执行时间达到本组实验的最低值 25.928071 秒，加速比为 12.80。

当分块大小继续增加到 512 时，执行时间明显上升，说明分块大小并非越大越好。

原实验报告对这一现象的解释是：

- m = 256 时，三个矩阵块的工作集约为 768 KB，按 12 个线程估算，总工作集约为 9 MB，能够较好地利用 15 MB L3 Cache。
- m = 512 时，按相同方式估算，总工作集约为 36 MB，超过 L3 Cache 容量，访存开销增加。

这部分属于原报告基于缓存容量作出的解释，尚不能等同于硬件性能计数器对实际 Cache 命中情况的直接测量。

## 7. 实验结论

矩阵分块能够显著改善朴素矩阵乘法的执行效率。

本组历史实验中，m = 256 取得最佳性能，而不是理论初始选择 m = 128。

这说明实际最优分块参数不仅与单个 Cache 的容量有关，还可能受到多线程工作集、缓存共享关系和访存行为的影响。

因此，分块大小需要结合实际硬件环境和实验结果确定，不能简单依据单一 Cache 容量进行推断。
