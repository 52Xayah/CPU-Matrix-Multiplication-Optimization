# Part02 · Matrix_mul.c 整体实现架构与执行流程

## 1. 研究对象

本章节以自主实现的 `Matrix_mul.c` 为研究对象，分析程序整体结构、主要函数职责、矩阵分块方式以及各优化模块之间的协作关系。

该程序使用 C 语言实现单精度浮点矩阵乘法，结合多级分块、B 矩阵 Packing、AVX SIMD 微内核和 OpenMP 多线程并行技术。

与普通矩阵乘法不同，该实现最终只输出结果矩阵的迹（Trace），因此使用线程私有的局部结果块完成计算，并提取主对角线元素，而不需要长期保存完整的结果矩阵。

## 2. 核心参数

| 参数 | 数值 | 作用 |
|---|---:|---|
| MC | 64 | 输出矩阵行方向分块 |
| NC | 128 | 输出矩阵列方向分块 |
| KC | 256 | K 方向分块 |
| MR | 4 | 微内核行数 |
| NR | 16 | 微内核列数 |

MC、NC、KC 属于较大层次的矩阵分块参数，MR、NR 则控制底层微内核的计算尺寸。

## 3. 程序整体执行流程

程序执行过程如下：

1. 读取矩阵规模 N 和输入种子 seed。
2. 申请矩阵 A、B 的内存空间。
3. 使用 matrix_gen 初始化矩阵。
4. 根据 MC、NC 计算输出矩阵分块数量。
5. 创建 OpenMP 并行区域。
6. 每个线程申请独立的 Bp、Ct 工作缓冲区。
7. 使用动态调度分配输出矩阵块。
8. 将 K 维度划分为 KC 大小的计算区间。
9. 对 B 矩阵进行 Packing。
10. 调用 AVX 4×16 微内核完成计算。
11. 使用边界微内核处理剩余行。
12. 提取结果矩阵主对角线元素。
13. 计算 Trace 并输出。

## 4. 多线程任务组织

程序通过 MC、NC 将输出矩阵划分为多个任务。

任务数量：

nI = ceil(N / MC)

nJ = ceil(N / NC)

ntiles = nI × nJ

当 N = 8192 时：

- nI = 128
- nJ = 64
- ntiles = 8192

每个任务负责一个 64×128 的输出区域。

OpenMP 使用：

#pragma omp for schedule(dynamic, 1)

将任务动态分配给线程。

每个线程拥有独立的 Bp 和 Ct 工作缓冲区。

## 5. 工作缓冲区

| 缓冲区 | 尺寸 | 容量 |
|---|---|---:|
| Bp | KC × NC | 128 KB |
| Ct | MC × NC | 32 KB |

每个线程需要约160 KB 的显式工作缓冲区。

Bp 用于保存 Packing 后的 B 矩阵面板，Ct 用于保存当前输出块的累加结果。

## 6. B 矩阵 Packing

程序按照 NR = 16 的宽度组织 B 矩阵数据。

每个 K 位置对应连续的16个单精度浮点数。

当最后一个面板不足16列时，剩余位置补零。

这种布局使微内核可以通过连续向量加载获得 B 矩阵数据。

## 7. AVX 微内核

核心计算函数为 `kern4x16()`。

该函数一次处理4行、16列。

内部使用8个 `__m256` 累加器，每个寄存器保存8个单精度浮点数，总计覆盖64个输出元素。

计算过程中，程序从 A 中广播标量，从 Packing 后的 B 中加载向量，通过 AVX 乘法与加法完成累加。

该实现使用 `_mm256_mul_ps` 和 `_mm256_add_ps`，没有显式调用 FMA Intrinsics。

## 8. 边界处理

程序使用 `kern_edge()` 处理不足 MR = 4 行的剩余区域。

列方向不足 NR = 16 时，通过 Packing 阶段补零。

这种设计使主要微内核能够保持固定计算尺寸，同时兼顾非整除矩阵规模。

## 9. Trace 计算

程序通过局部结果块 Ct 获取主对角线元素，并保存到 diag 数组。

最终计算：

Trace(C) = Σ C[i][i]

程序只输出 Trace，不输出完整矩阵 C。

## 10. 整体设计特点

该实现具有以下特点：

1. 通过多级分块组织矩阵乘法计算。
2. 通过 B 矩阵 Packing 改变数据布局。
3. 使用 AVX 4×16 微内核提高数据级并行能力。
4. 使用 OpenMP 动态调度组织多线程任务。
5. 通过线程私有工作缓冲区减少计算过程中的共享写入。
6. 只保留最终需要的对角线结果。
