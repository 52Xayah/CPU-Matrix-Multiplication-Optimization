# Part08 · B 矩阵 Packing 复用优化方案设计

> 状态更新（2026-11-15）：保留本文作为研究过程记录。按用户要求停止源码优化，后续仅整理文档与记录实验数据；本文中的优化路线或方案不代表已验证的性能收益。

## 1. 研究背景

当前 Matrix_mul.c 使用多级矩阵分块、B 矩阵 Packing、AVX 微内核和 OpenMP 实现高性能矩阵乘法。

源码分析发现，Packing 操作位于输出矩阵块任务内部。

不同输出行块在列块坐标 jc 和 K 分块 k0 相同的情况下，需要访问相同的 B 矩阵数据。

但是当前实现会为每个输出行块重新执行 Packing，产生重复的数据复制。

本研究希望通过调整任务组织方式，提高 B 面板复用率。

## 2. 当前实现分析

实验参数：

| 参数 | 数值 |
|---|---:|
| N | 8192 |
| MC | 64 |
| NC | 128 |
| KC | 256 |
| MR | 4 |
| NR | 16 |

分块数量：

- 行方向：128。
- 列方向：64。
- K 方向：32。

一个 B 面板的大小：

256 × 128 × 4 = 128 KiB。

整个 B 矩阵大小：

8192 × 8192 × 4 = 256 MiB。

对于固定的 jc 和 k0，B 面板会被128个不同的输出行块重复打包。

因此累计 Packing 写入量为：

128 × 256 MiB = 32 GiB。

该结果表示逻辑写入量，不等于实际 DRAM 流量。

## 3. 优化方案 A：输出行块分组

### 3.1 核心思想

将多个相邻输出行块划分为一个任务。

同一任务内部：

1. Packing 当前 B 面板。
2. 使用该面板计算第一个输出行块。
3. 使用同一面板计算第二个输出行块。
4. 继续处理分组内其他行块。

这样能够避免分组内部重复 Packing。

### 3.2 分组参数

定义 G 为每个任务包含的输出行块数量。

| G | 任务数量 | 理论 Packing 写入量 |
|---:|---:|---:|
| 1 | 8192 | 32 GiB |
| 2 | 4096 | 16 GiB |
| 4 | 2048 | 8 GiB |
| 8 | 1024 | 4 GiB |

### 3.3 工作缓冲区

原始实现每个线程使用：

- Bp：128 KiB。
- Ct：32 KiB。

新版本使用：

- Bp：128 KiB。
- CtGroup：G 个 Ct 工作块。

CtGroup 大小：

G × MC × NC × 4 Bytes。

| G | Bp + CtGroup |
|---:|---:|
| 1 | 160 KiB |
| 2 | 192 KiB |
| 4 | 256 KiB |
| 8 | 384 KiB |

服务器每个物理核心的 L2 Cache 为256 KB。

因此需要权衡 Packing 复用收益与工作集增长带来的 Cache 压力。

优先测试 G=2，随后对比 G=4 和 G=8。

### 3.4 线程安全

继续采用每线程独立的 Bp 和 CtGroup。

不同任务负责不同的输出矩阵区域。

不需要引入共享 Bp，也不需要额外锁机制。

### 3.5 正确性

保持每个输出元素的 K 方向累加顺序。

完成所有 K 分块后，再提取各行块对应的对角线元素。

通过与原始版本的 Trace 对比验证正确性。

## 4. 优化方案 B：跨线程共享 Bp

该方案进一步研究不同线程是否可以复用同一个 B 面板。

主要步骤：

1. 由一个线程负责 Packing。
2. 其他线程等待 Packing 完成。
3. 多个线程共享读取 Bp。
4. 各线程分别计算自己的输出区域。

潜在问题：

- OpenMP 同步开销。
- 共享数据访问。
- NUMA 远程访问。
- 输出累加状态管理。

该方案实现复杂度较高，暂不作为第一阶段优化目标。

## 5. 两种方案对比

| 维度 | 行块分组 | 跨线程共享 |
|---|---|---|
| Packing 复用 | 分组内部 | 多线程 |
| Bp | 线程私有 | 共享 |
| 同步需求 | 较少 | 较多 |
| NUMA 风险 | 相对较低 | 相对较高 |
| 实现难度 | 中等 | 较高 |

## 6. 实验设计

### 6.1 实验变量

固定矩阵规模 N=8192。

比较 G=1、2、4、8。

首先固定12线程，再选择24线程进行补充对照。

### 6.2 实验指标

- Trace。
- 执行时间。
- 相对加速比。
- Packing 次数。
- Packing 逻辑写入量。
- 线程数量。
- 分组大小。
- 编译参数。

### 6.3 正确性测试

选取 N=65、129、257、8192 等规模。

覆盖常规计算、行方向边界和列方向边界情况。

### 6.4 性能评价

加速比：

Speedup = T_baseline / T_optimized

性能提升率：

Improvement = (T_baseline - T_optimized) / T_baseline × 100%

每种配置使用相同编译参数和运行环境，进行多次测试，采用中位数作为代表结果。

## 7. 当前研究结论

当前实现存在可以从源码确认的重复 B Packing。

通过将多个输出行块组合成一个任务，可以在不引入跨线程共享缓冲区的情况下复用 B 面板。

方案 A 在实现复杂度、线程安全和数据复用之间具有较好的平衡。

但 G 增大也会增加 CtGroup 的工作集，可能带来 Cache 压力。

因此不能仅根据理论 Packing 写入量判断最优分组大小，必须结合实际服务器进行测试。
