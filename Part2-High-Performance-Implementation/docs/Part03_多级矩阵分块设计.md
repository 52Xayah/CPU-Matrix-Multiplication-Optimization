# Part03 · 多级矩阵分块设计与 Cache 层次分析

## 1. 研究目的

本章节研究 `Matrix_mul.c` 中 MC、NC、KC 三个分块参数的作用，结合实际服务器的 Cache 层次结构，分析矩阵分块与数据局部性之间的关系。

研究重点是理解分块如何改变矩阵乘法的数据访问方式，以及不同分块尺寸对工作集规模、数据复用和任务粒度的影响。

## 2. 分块参数

源码定义：

```c
#define MC 64
#define NC 128
#define KC 256
#define MR 4
#define NR 16
```

其中：

| 参数 | 数值 | 作用 |
|---|---:|---|
| MC | 64 | 输出矩阵行方向分块 |
| NC | 128 | 输出矩阵列方向分块 |
| KC | 256 | K 方向分块 |
| MR | 4 | 微内核行数 |
| NR | 16 | 微内核列数 |

MC、NC、KC 控制较大范围的矩阵分块，MR、NR 控制底层微内核的计算尺寸。

## 3. 分块计算过程

矩阵乘法：

C = A × B

其中：

C(i,j) = Σ A(i,k) × B(k,j)

程序首先通过 MC、NC 将输出矩阵划分为多个计算任务，再沿着 K 维度使用 KC 分段累加。

每个计算任务负责一个输出矩阵区域：

C_tile = A_tile × B_tile

其中：

- A_tile 的最大尺寸为 64×256。
- B_tile 的最大尺寸为 256×128。
- C_tile 的最大尺寸为 64×128。

Ct 在 K 方向计算开始之前初始化一次，之后各个 KC 分块的部分结果持续累加到 Ct。

## 4. N=8192 时的任务规模

当 N=8192：

nI = 8192 / 64 = 128

nJ = 8192 / 128 = 64

ntiles = 128 × 64 = 8192

K 方向分块数量：

8192 / 256 = 32

每个输出块需要经过32轮 K 方向计算。

## 5. 工作集大小估算

矩阵采用单精度 float，每个元素占4 Bytes。

### 5.1 A 矩阵分块

64 × 256 × 4 = 65536 Bytes = 64 KB

### 5.2 B 矩阵分块

256 × 128 × 4 = 131072 Bytes = 128 KB

### 5.3 C 局部结果块

64 × 128 × 4 = 32768 Bytes = 32 KB

### 5.4 总工作集

64 KB + 128 KB + 32 KB = 224 KB

该数值是逻辑工作集估算，不代表所有数据在运行时同时驻留于某一级 Cache。

程序显式分配的线程私有工作缓冲区为：

- Bp：128 KB
- Ct：32 KB

合计160 KB。

A 分块直接从原始矩阵读取，并未复制到独立的 A 工作缓冲区。

## 6. 与服务器 Cache 的关系

服务器实测 Cache：

| Cache | 容量 |
|---|---:|
| L1 Data | 32 KB |
| L2 | 256 KB |
| L3 | 15 MB / Socket |

逻辑工作集224 KB小于256 KB的 L2 容量，但不能据此断言所有工作数据都能完全驻留在 L2 中。

实际缓存行为还受到数据访问顺序、线程执行、其他缓存占用和内存访问模式影响。

## 7. MC、NC、KC 的作用分析

### 7.1 MC = 64

控制输出块的行方向尺寸。

MR=4，因此每个输出块最多包含：

64 / 4 = 16 组微内核。

同一个 B 面板可以被多个行方向微内核复用。

增大 MC 有利于增加行方向复用，但会扩大 A 和 C 的工作集。

### 7.2 NC = 128

控制输出块的列方向尺寸。

NR=16，因此：

128 / 16 = 8 个 B 面板。

NC 影响 B Packing 的规模、Ct 的容量以及输出任务数量。

### 7.3 KC = 256

控制 K 方向的分块尺寸。

当 N=8192 时，共需要32轮计算。

增大 KC 可以减少 K 方向循环次数和分段开销，但会扩大单次计算的数据规模。

减小 KC 可以降低单次工作集，但可能增加循环和 Packing 开销。

## 8. AVX 微内核与分块之间的关系

底层微内核使用4×16计算尺寸。

对于 KC=256：

- A 的4行数据规模为4 KB。
- B 的16列面板规模为16 KB。
- 单个输出微块规模为256 Bytes。

这些数据切片与32 KB的 L1 Data Cache 存在一定关联。

不过，理论数据规模不能直接替代真实 Cache 命中率测试。

## 9. NUMA 架构的影响

服务器包含两个 NUMA 节点，每个节点对应一个处理器 Socket。

每个 Socket 拥有独立的15 MB L3 Cache。

多线程运行时，需要进一步研究：

1. 线程绑定与 CPU 亲和性。
2. NUMA 内存首次触碰策略。
3. 线程私有缓冲区的内存位置。
4. 动态任务调度与跨节点数据访问。
5. 不同线程配置下的缓存与内存带宽表现。

## 10. 本章结论

MC、NC、KC 分别控制矩阵乘法的行方向、列方向和 K 方向计算粒度。

它们共同决定：

- 单个计算任务的规模。
- B 矩阵 Packing 的数据量。
- 局部结果块的容量。
- 数据复用方式。
- 线程任务粒度。
- 单次计算的工作集规模。

当前源码采用 MC=64、NC=128、KC=256。

这组参数与服务器的 L1、L2、L3 缓存容量存在明确的分析联系，但尚不能仅凭理论容量证明其为最优组合。

## 11. 后续研究

后续需要进一步研究：

- MC、NC、KC 的联合参数调优。
- 不同参数组合的运行时间。
- 单线程与多线程下的参数差异。
- 不同 NUMA 放置方式对性能的影响。
- Packing 与微内核之间的数据复用关系。

所有最优参数结论必须由真实实验数据支持。
