# Part04 · B 矩阵 Packing 数据打包技术分析

## 1. 研究目的

本章节研究 `Matrix_mul.c` 中 B 矩阵 Packing 的实现原理，分析其数据布局、内存对齐方式、数据复用机制以及对 AVX 微内核的支持。

Packing 的核心目标是将原始矩阵中需要参与当前计算的数据重新组织到连续的缓冲区中，使微内核能够采用固定的数据访问模式。

## 2. 原始矩阵存储方式

程序使用一维数组保存矩阵 B，采用 Row-major 行优先存储。

元素地址：

B[i][j] = B + i × N + j

在原始矩阵中，相邻行之间的地址跨度为：

N × sizeof(float)

当 N=8192 时：

8192 × 4 = 32768 Bytes = 32 KB

虽然同一行的连续16个元素可以直接读取，但不同 K 位置的数据在原始矩阵中存在较大的行跨度。

## 3. Packing 的基本思想

源码定义：

NR = 16

每个 B 面板包含16列。

Packing 将当前 K 分块中的 B 数据按照面板组织：

B_panel[p][k][j]

其中：

- p：当前面板编号。
- k：当前 K 分块中的位置。
- j：面板内部的列位置，范围为0至15。

Packing 后，每个 K 位置对应连续16个 float。

相邻 K 位置之间的地址跨度为：

16 × 4 = 64 Bytes

这样可以使微内核连续读取 B 数据。

## 4. Packing 核心实现

```c
int npan = (nc + NR - 1) / NR;

for (int p = 0; p < npan; p++) {
    int j0 = p * NR;
    int w = nc - j0 < NR ? nc - j0 : NR;

    float *dst = Bp + (long)p * kc * NR;

    for (int k = 0; k < kc; k++) {
        const float *src =
            B + (long)(k0 + k) * N + jc + j0;

        int j = 0;

        for (; j < w; j++)
            dst[j] = src[j];

        for (; j < NR; j++)
            dst[j] = 0.0f;

        dst += NR;
    }
}
```

实现过程：

1. 计算当前输出块需要的面板数量。
2. 确定当前面板的列起点。
3. 从原始矩阵 B 读取当前 K 位置的连续数据。
4. 将数据复制到 Bp。
5. 对不足16列的面板进行补零。
6. 目标地址每次前进16个 float。

## 5. Packing 缓冲区大小

程序使用：

```c
posix_memalign(
    (void **)&Bp,
    64,
    KC * NC * sizeof(float)
);
```

根据当前参数：

KC = 256

NC = 128

float = 4 Bytes

因此：

256 × 128 × 4 = 131072 Bytes

即128 KB。

当 NC=128 时，每个输出块包含8个 B 面板。

每个面板：

256 × 16 × 4 = 16 KB

8个面板共128 KB。

## 6. 内存对齐设计

Bp 起始地址采用64字节对齐。

每个 K 位置包含16个 float：

16 × 4 = 64 Bytes

因此每个 K 位置的起始地址保持64字节对齐。

微内核使用：

```c
_mm256_load_ps(bp);
_mm256_load_ps(bp + 8);
```

每次加载8个 float，即32字节。

64字节对齐的 Bp 布局能够满足上述 AVX 对齐加载要求。

## 7. Packing 的性能价值

### 7.1 连续访问

Packing 后，微内核不再需要根据原始矩阵的 N 计算跨行地址。

通过：

```c
bp += NR;
```

即可访问下一个 K 位置的数据。

### 7.2 数据复用

MC=64，MR=4。

因此一个输出块在行方向上最多需要：

64 / 4 = 16 组微内核。

相同的 B 面板可以供这些微内核重复使用。

每个微内核内部又会将同一组 B 向量用于4行计算。

### 7.3 简化计算内核

Packing 将原始矩阵的复杂地址计算、面板提取和边界处理放在微内核之外。

微内核只需要读取已经整理好的 Bp。

## 8. Packing 的成本与局限

Packing 需要额外读取原始 B、写入 Bp，并由微内核再次读取 Bp。

因此会增加数据复制和内存访问开销。

它是否能够带来性能收益，取决于打包数据的复用程度以及额外复制成本。

当前实现采用线程私有的 Bp。

其优点是避免多个线程同时写入同一 Packing 缓冲区。

但由于 Packing 位于每个输出矩阵任务内部，不同输出行块可能重复打包相同的 B 数据。

例如：

- ic=0、jc=0
- ic=64、jc=0
- ic=128、jc=0

在相同 K 分块下，这些任务需要的 B 面板相同，但当前实现会分别进行 Packing。

这属于后续值得研究的优化空间。

## 9. 边界处理

当最后一个面板不足16列时，程序使用0补齐剩余位置。

由于：

A × 0 = 0

因此补齐位置不会影响有效矩阵列的计算结果。

对于 N=8192：

- N 能被 NC=128 整除。
- NC 能被 NR=16 整除。

所以该规模下不需要触发列方向补零逻辑。

## 10. 本章结论

B 矩阵 Packing 是当前矩阵乘法实现中连接大规模分块与底层 AVX 微内核的重要环节。

其主要价值包括：

1. 将原始矩阵中的数据重新组织为固定宽度的面板。
2. 提供连续的 K 方向数据访问。
3. 保证打包缓冲区满足 AVX 对齐加载要求。
4. 支持微内核对 B 数据进行重复利用。
5. 将数据布局处理与实际计算内核分离。

同时，Packing 也带来额外数据复制成本。

当前实现采用线程私有 Packing 缓冲区，但存在不同输出行块重复打包 B 面板的可能性。

后续可以研究 B 面板跨任务复用、共享 Packing 与 NUMA 局部性之间的关系。
