# Part07 · Matrix_mul.c 性能瓶颈分析与优化路线图

## 1. 研究目的

在完成 Matrix_mul.c 的整体架构和主要优化模块分析后，本章节进一步识别当前实现中值得研究的性能问题，并制定后续优化路线。

研究遵循以下原则：

- 源码中能够直接确认的设计特点，作为事实记录。
- 具有理论依据但尚未测量的性能问题，作为待验证假设。
- 所有性能提升结论必须有对应实验数据支持。

## 2. 当前实现的主要性能特征

当前程序采用：

- MC=64、NC=128、KC=256 多级分块。
- B 矩阵 Packing。
- AVX 4×16 微内核。
- 8个 AVX 向量累加器。
- OpenMP Dynamic Scheduling。
- 每线程独立的 Bp 和 Ct 工作缓冲区。

## 3. 潜在性能瓶颈

### 3.1 重复 B Packing

当前 Packing 操作位于输出矩阵块的任务循环内部。

不同输出行块在列坐标和 K 分块相同的情况下，会重复打包相同的 B 数据。

对于 N=8192：

- 行方向分块数：128。
- 列方向分块数：64。
- K 方向分块数：32。
- 每个输出矩阵块对应4 MiB的 B Packing 数据。
- 全部输出行块累计 Packing 写入量为32 GiB。

这相当于原始 B 矩阵256 MiB数据的128倍累计打包量。

该数值表示逻辑 Packing 写入量，不代表实际 DRAM 流量。

后续需要研究 B 面板跨输出行块复用的可行性。

### 3.2 NUMA 内存局部性

A、B 矩阵在 OpenMP 并行区域之前由主线程串行初始化。

在默认 First-Touch 策略下，内存页面可能集中在初始化线程所在节点。

后续其他 NUMA 节点的线程可能需要远程访问这些数据。

需要研究：

- 并行初始化。
- NUMA 内存交错分配。
- CPU 亲和性。
- 内存首次触碰策略。

### 3.3 OpenMP 调度开销

当前使用：

`schedule(dynamic, 1)`

对于 N=8192，输出矩阵块尺寸相同，计算量基本一致。

需要对比静态调度与动态调度，分析任务调度开销和负载均衡。

### 3.4 AVX 微内核

当前使用独立的 AVX 乘法和加法 Intrinsics。

后续需要分析：

- 实际生成的机器指令。
- 向量寄存器使用情况。
- 指令调度。
- CPU 指令集能力。
- 编译器优化效果。

### 3.5 分块参数

当前 MC、NC、KC 固定。

需要研究三个参数的联合配置，以及它们与 L1、L2、L3 Cache 的关系。

### 3.6 工程完整性

当前程序缺少内部计时，部分内存分配缺少完整错误处理，正常退出前没有显式释放全部动态分配的内存。

后续应在不破坏原始实现的前提下，建立独立的测试和优化版本。

## 4. 优化优先级

| 优先级 | 研究方向 | 主要目标 |
|---|---|---|
| P0 | 性能基线与正确性验证 | 建立可信测量基础 |
| P1 | B Packing 复用 | 减少重复数据打包 |
| P1 | NUMA 优化 | 提高本地内存访问比例 |
| P2 | OpenMP 调度 | 降低调度开销 |
| P2 | 分块参数调优 | 改善缓存利用 |
| P3 | AVX 微内核 | 提高指令执行效率 |

## 5. 优化实验原则

每次优化应遵循：

1. 保留原始版本。
2. 单独建立优化版本。
3. 记录修改内容和技术原因。
4. 保证输入条件一致。
5. 验证 Trace 正确性。
6. 记录编译参数和运行环境。
7. 保存原始运行日志。
8. 生成可追溯的性能对比结果。

不得将不同源码版本的历史运行时间混合比较。

## 7. 当前阶段结论

当前实现已经结合分块、Packing、AVX 和 OpenMP 形成较完整的多层次优化结构。

源码分析发现，重复 B Packing 和 NUMA 内存放置是最值得进一步研究的两个方向。

动态调度、分块参数和 AVX 指令优化也具有进一步调优的空间。

目前这些属于源码分析和待验证的优化假设，不应提前认定为已经获得性能收益。
